# 02 — EMU Creator Product Model

## Product proposition

The opportunity is not to make EMU “simpler” by removing depth.

It is to make the first successful creative outcome dramatically easier while preserving a path into deeper control.

> **Easy to start, deep enough to grow with the creator.**

This is a creator-tool philosophy similar to what successful consumer-creation tools have done in video editing: users can begin before they understand the professional vocabulary, but advanced capability remains available as their ambition grows.

The analogy to CapCut / 剪映 is about **product philosophy**, not feature-for-feature copying.

---

## 1. One product, three levels of depth

The ideal experience is progressive disclosure inside the same project.

### Level 1 — Quick / Template

User intent:

> “I just want my lights to work with this song and look good.”

The user should be able to:

- import a song
- choose a visual style / template
- choose a simple setup
- preview the result
- make a few high-level changes
- start creating in minutes

Possible creator-facing controls:

- calm / energetic
- restrained / expressive
- narrow / wide
- subtle / dramatic
- smooth / rhythmic
- first chorus / final chorus intensity
- colour family
- amount of motion

The user should not need to understand DMX, Art-Net or detailed fixture logic before seeing value.

---

### Level 2 — Creator

User intent:

> “This is close, but I want it to feel more like me.”

Reveal more control:

- song sections
- repeated-section variation
- musical-role emphasis
- sync / delay / drift / counterpoint
- spatial focus
- width / compression
- movement
- density
- transition
- creator-defined visual language

This is where Music-to-Light Visual Grammar becomes useful.

The creator can move from:

> “Give me a good-looking result.”

to:

> “Help me express this specific intention.”

---

### Level 3 — Advanced / Lighting

User intent:

> “I want precise control over how the system works.”

Preserve or expose deeper capabilities:

- fixtures
- patching
- DMX
- MIDI / DAW control
- automation
- cue logic
- detailed effect parameters
- mapping
- repeatable professional workflows

The goal is not to force every creator into this level.

It is to make sure users who grow into lighting do not outgrow EMU immediately.

---

## 2. Templates are an entry point, not the ceiling

A template should be:

- immediately useful
- editable
- inspectable
- educational

A strong template can teach the user:

> “The bass is changing spatial width here, not brightness.”

or:

> “The second chorus uses variation rather than repeating the first chorus.”

That means templates become both:

- a speed tool
- a learning tool

The user journey can be:

**use template → customize template → understand template → build your own visual language**

---

## 3. A creator-growth ladder

The product should support the psychological progression:

> **I just want cool lights**  
> → **I want this to feel more like me**  
> → **I want to understand why it works**  
> → **I want full control**

This is more valuable than splitting beginners and advanced users into disconnected tools.

---

## 4. Outcome-first onboarding

Do not begin with professional terminology.

Begin with creator outcomes:

- “I want a dance-video setup.”
- “I want a small live-band setup.”
- “I want a bedroom creator setup.”
- “I want a dramatic red performance.”
- “I want a soft ambient performance.”

Then reveal the technical implementation behind the outcome.

Possible starter packages:

- Dance Studio Starter
- K-pop Performance
- Small Live Band
- Bedroom Musician
- Creator MV / Performance Video

Each could combine:

- recommended physical layout
- compatible ENTTEC hardware
- EMU project template
- tutorial
- finished example

---

## 5. Creator workflow compatibility

A creator does not experience EMU in isolation.

A common workflow may be:

**music → choreography / performance → physical lighting → camera → editing → social publishing**

EMU shapes the **physical performance before capture**.

Video tools such as CapCut / 剪映 shape the **captured performance after capture**.

A useful product direction is therefore workflow compatibility.

### Stage A — Media handoff
- import final / reference audio
- import reference video
- export useful preview media

### Stage B — Timeline alignment
- share section markers or timing references where practical
- reduce duplicate work between lighting and video editing

### Stage C — Preview / round-trip
- use edited video as visual reference inside the lighting workflow
- bring lighting previews back into the editing workflow

### Stage D — deeper integration
Only if official APIs / project interfaces make it practical.

Do not make deep third-party integration a dependency for the core product.

---

## 6. Product principles

1. **First success before first lesson** — let users create before teaching everything.
2. **Progressive disclosure** — complexity appears when the user asks for it.
3. **Templates remain editable** — never trap the user inside presets.
4. **Professional depth remains real** — beginners can grow without switching tools immediately.
5. **Creator language before engineering language** — start from outcomes and expression.
6. **Interoperability before lock-in** — make ENTTEC the easiest path, not the only possible path.
7. **The project should survive mode changes** — Quick, Creator and Advanced are different views of the same work.

---

## 7. Strategic consequence

If this model works, EMU stops being only a tool for people who already know they need lighting software.

It becomes an **instant creative tool** for individuals and small teams who want to make music visible.

That changes the addressable market.

# 中文版

## 02 — EMU Creator Product Model

### 产品命题

机会不是通过删功能把 EMU 变成“傻瓜软件”。

而是让用户第一次做出成功作品的门槛大幅下降，同时保留继续深入的能力。

> **Easy to start, deep enough to grow with the creator.**

这和剪映这类成功 creator tool 的产品哲学很像：用户不必先学会所有专业术语才能开始，但随着创作野心增长，工具仍然有足够深度。

这里借鉴的是**产品哲学**，不是把 EMU 做成剪映的功能复制品。

---

## 1. 一个产品，三层深度

理想状态是在同一个 project 里逐渐展开复杂度。

### Level 1 — Quick / Template

用户想法：

> “我只是想让灯跟这首歌配起来，而且看起来不错。”

应该可以：

- 导入歌曲
- 选一个 visual style / template
- 选简单 setup
- preview
- 做少量高层调整
- 几分钟内开始创作

可以暴露给 creator 的控制：

- calm / energetic
- restrained / expressive
- narrow / wide
- subtle / dramatic
- smooth / rhythmic
- 第一次 / 最后一次副歌强度
- 色彩范围
- movement 程度

用户不需要先懂 DMX、Art-Net 或复杂 fixture logic 才能看到价值。

---

### Level 2 — Creator

用户开始想：

> “这个已经不错，但我想让它更像我。”

逐渐展开：

- song section
- repeated-section variation
- musical-role emphasis
- sync / delay / drift / counterpoint
- spatial focus
- width / compression
- movement
- density
- transition
- creator-defined visual language

这就是 Music-to-Light Visual Grammar 真正进入产品的地方。

用户从：

> “给我一个好看的结果。”

进入：

> “帮我表达这个具体意图。”

---

### Level 3 — Advanced / Lighting

用户开始想：

> “我要精确控制系统到底怎么工作。”

保留或展开：

- fixture
- patching
- DMX
- MIDI / DAW
- automation
- cue logic
- detailed effect parameter
- mapping
- 可重复专业 workflow

不是要求每个人都进入这一层，而是确保真正成长起来的用户不会很快被迫离开 EMU。

---

## 2. Template 是入口，不是天花板

好的 template 应该：

- 立刻能用
- 可以编辑
- 可以拆开看
- 能成为教学材料

用户可以反向学会：

> “原来这里 bass 影响的是 spatial width，不是 brightness。”

或者：

> “原来第二次副歌不是复制，而是 variation。”

于是 template 同时是：

- speed tool
- learning tool

成长路线：

**用 template → 改 template → 看懂 template → 建立自己的 visual language**

---

## 3. Creator 成长阶梯

产品应该支持这种心理变化：

> **我只想要酷一点的灯**  
> → **我想让它更像我**  
> → **我想知道它为什么这样工作**  
> → **我要完整控制**

这比把新手和进阶用户拆成完全不同产品更有长期价值。

---

## 4. Outcome-first onboarding

不要从专业术语开始。

先从 creator outcome 开始：

- “我要一个舞蹈视频 setup。”
- “我要一个小型 live band setup。”
- “我要 bedroom creator setup。”
- “我要 dramatic red performance。”
- “我要 soft ambient performance。”

再逐渐让用户看到背后的技术实现。

可能的 starter package：

- Dance Studio Starter
- K-pop Performance
- Small Live Band
- Bedroom Musician
- Creator MV / Performance Video

每个 package 可以包含：

- 推荐物理布局
- ENTTEC hardware
- EMU project template
- tutorial
- finished example

---

## 5. Creator workflow compatibility

Creator 不会只使用 EMU。

完整流程更可能是：

**音乐 → choreography / performance → 真实灯光 → camera → 剪辑 → 社交平台发布**

EMU 负责的是：

> **拍摄发生之前，真实空间里的视觉。**

剪映 / CapCut 负责的是：

> **拍摄完成之后，对画面做编辑和包装。**

所以值得考虑的是 workflow compatibility。

### Stage A — Media handoff
- 导入最终 / reference audio
- 导入 reference video
- 导出有用 preview

### Stage B — Timeline alignment
- 在可行时共享 section marker / timing reference
- 减少灯光和视频编辑之间重复劳动

### Stage C — Preview / round-trip
- 把剪好的视频作为灯光制作 reference
- 把灯光 preview 再带回视频 workflow

### Stage D — Deep integration
只有官方 API / project interface 允许时再考虑。

第三方深度集成不应该成为核心产品成立的前提。

---

## 6. 产品原则

1. **First success before first lesson** —— 先让用户做出来，再教所有概念。
2. **Progressive disclosure** —— 用户需要时再展开复杂度。
3. **Template 可编辑** —— 不能把用户困在 preset。
4. **专业深度真实存在** —— 用户成长后仍然可以继续用。
5. **Creator language before engineering language** —— 从结果和表达开始。
6. **Interoperability before lock-in** —— 让 ENTTEC 成为最顺手的路径，而不是唯一路径。
7. **模式切换不破坏 project** —— Quick、Creator、Advanced 只是同一个作品的不同视图。

---

## 7. 战略结果

如果这个模型成立，EMU 就不再只服务那些已经知道自己需要 lighting software 的人。

它会成为个人和小团队把音乐变成视觉表达的**即时创作工具**。

这会直接改变 ENTTEC 可以服务的市场边界。
