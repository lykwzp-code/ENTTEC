# 08 — 180-Day Execution Plan

## Goal

Use six months to test the strategy with evidence.

Do not join and immediately build the full vision.

Method:

> **Learn → Discover → Experiment → Prove**

---

## Days 0–30 — Learn

### Product
- use EMU as a beginner creator
- use EMU again as an advanced user
- understand where Quick / Creator / Advanced experiences could differ
- understand ELM boundaries
- understand hardware / deployment ecosystem

### Organisation
- shadow Product, Engineering, Support, Sales and Marketing
- map decision rights
- clarify resource allocation
- identify what Product Specialist owns

### Evidence
- review support themes
- review creator / customer cases
- study where users drop out or need expert help

### Deliverables
- product / ecosystem map
- user ladder
- friction map
- decision-rights map
- first research plan

---

## Days 31–60 — Discover

### Creator research
Interview:
- musicians
- dance creators
- small creative teams
- existing EMU users
- people who currently do not use lighting tools

Questions:
- what outcome do they want?
- what feels too technical?
- when do templates help?
- when do they want more control?
- what would make them invest in physical lighting?

### Professional research
Interview:
- ELM users
- designers
- integrators

Understand:
- what professional depth must never be lost
- which creator-originated ideas might matter professionally

### Output
- top 3 creator problems
- first progressive-complexity prototype hypothesis
- first category-expansion test
- first Music-to-Light research plan

---

## Days 61–90 — Experiment

### Product experiment
Test one low-friction creator flow.

Example:
- import music
- choose setup
- choose template
- customize one section
- reveal advanced controls only when requested

Measure:
- time to first useful result
- completion
- first customization
- confusion points

### Market experiment
Run 2–3 rights-cleared Reimagined in Light pilots.

Include:
- at least one dance / performance creator
- clear path into template / tutorial / EMU trial

### Research experiment
Run first Music-to-Light Visual Grammar session with creators.

---

## Months 4–6 — Prove

If early evidence is strong:

### Product
- refine progressive complexity
- test editable templates
- test creator-language controls
- decide which ideas deserve Engineering investment

### Growth
- repeat content format
- test studio / dance creator demand
- measure qualified creator acquisition
- test starter setup / hardware attachment

### Co-creation
- launch small Artist Lab pilot
- recruit 3–5 design partners
- capture Artist Intent Cards

### AI
Only prototype AI if manual research shows a repeated translation problem.

### Portfolio
Only assess EMU → ELM graduation after creator value is proven.

---

## KPI hierarchy

### Acquisition
- creator-sourced downloads
- tutorial-to-product conversion
- inbound creator / studio interest

### Activation
- time to first expressive show
- template completion
- first customization
- setup success

### Retention
- repeat project creation
- repeat publishing
- creator independence

### Expansion
- hardware attachment
- advanced-mode adoption
- larger setup adoption
- relevant ELM progression

### Discovery
- validated problems
- insight-to-test time
- weak hypotheses killed early
- experiments repeated with multiple creators

---

## Six-month decision

Answer:

1. Can beginners get meaningful value quickly?
2. Do users want deeper customization after templates?
3. Is dance / performance creation a real adjacent market?
4. Does content acquire qualified users or only views?
5. Does Artist Lab generate useful product insight?
6. Is Music-to-Light Visual Grammar reusable across creators?
7. Is AI actually needed?
8. Is there a real creator → hardware → professional progression?
9. Does the Product Specialist role have enough ownership and resources to run the loop?

A good outcome may include killing weak ideas.

## 08 — 180 天执行计划

### 目标

用六个月证据验证整套策略。

不要入职就直接做完整大愿景。

方法：

> **Learn → Discover → Experiment → Prove**

---

## Days 0–30 — Learn

### Product
- 作为 beginner creator 使用 EMU
- 再以 advanced user 方式深入
- 理解 Quick / Creator / Advanced 应该怎样分层
- 理解 ELM 边界
- 理解 hardware / deployment ecosystem

### Organisation
- shadow Product、Engineering、Support、Sales、Marketing
- 画 decision right
- 确认 resource allocation
- 确认 Product Specialist ownership

### Evidence
- review support theme
- review creator / customer case
- 找用户在哪里退出、哪里必须求助专家

### Deliverables
- product / ecosystem map
- user ladder
- friction map
- decision-rights map
- first research plan

---

## Days 31–60 — Discover

### Creator research
访谈：
- 音乐人
- dance creator
- 小型创作团队
- existing EMU user
- 当前完全不用灯控工具的人

问：
- 他们真正想得到什么 outcome？
- 什么地方太技术化？
- template 什么时候有用？
- 什么时候开始想要更多控制？
- 什么会让他们愿意投资真实灯光？

### Professional research
访谈：
- ELM user
- designer
- integrator

理解：
- 哪些专业深度绝对不能丢
- 哪些来自 creator 的 idea 对 professional 也可能有价值

### Output
- top 3 creator problem
- first progressive-complexity hypothesis
- first category-expansion test
- first Music-to-Light research plan

---

## Days 61–90 — Experiment

测试一个低门槛 creator flow。

例如：
- import music
- choose setup

- customize one section
- 需要时才 reveal advanced control

- time to first useful result

- confusion point

### Market experiment

### Research experiment

如果 early evidence 强：

### Product
- refine progressive complexity
- 测 editable template
- 测 creator-language control
- 判断哪些 idea 值得 Engineering 投入

### Growth
- 重复 content format
- 测 studio / dance creator demand
- 测 qualified creator acquisition
- 测 starter setup / hardware attachment

### Co-creation
- 启动小规模 Artist Lab
- 3–5 个 design partner
- 建 Artist Intent Card

### AI
只有 manual research 证明 translation problem 重复出现，才做 AI prototype。

### Portfolio
creator value 被证明以后，才评估 EMU → ELM graduation。

---

## KPI hierarchy

### Acquisition
- creator-sourced download
- tutorial-to-product conversion
- creator / studio inbound

### Activation
- time to first expressive show
- template completion
- first customization
- setup success

### Retention
- repeat project creation
- repeat publishing
- creator independence

### Expansion
- hardware attachment
- advanced-mode adoption
- larger setup adoption
- 合适情况下的 ELM progression

- validated problem
- insight-to-test time

- 多 creator 重复验证

---

## 六个月核心判断

1. 新手能不能很快获得真实价值？
2. template 之后用户会不会想继续 customize？
3. dance / performance 是否真是邻近市场？
4. content 带来的是 qualified user 还是只有 views？
5. Artist Lab 是否产生高质量 product insight？
6. Music-to-Light Visual Grammar 是否能跨 creator 复用？
7. AI 是否真的需要？
8. 是否存在 creator → hardware → professional 的真实成长？
9. Product Specialist 有没有足够 ownership / resource 跑完整闭环？

好的结果也可以包括杀掉错误 idea。
