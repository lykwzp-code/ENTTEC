# 02 — Portfolio Strategy: EMU Discovers, ELM Scales

## Strategic proposition

**EMU discovers new creative language. ELM scales proven creative language into professional production.**

This is a hypothesis, not a statement of ENTTEC’s internal roadmap.

The public signal that makes the hypothesis worth exploring is that ELM 2026 includes a large set of GPU shader effects ported from EMU. That shows at least one real precedent for creative capability moving across the software portfolio.

---

## 1. Keep the products distinct

### EMU — creator-facing experimentation

Primary mental model:

> “I am a musician / DJ / performance creator. I want light to become part of how I express the music.”

Optimise for:

- expressive speed
- music-first vocabulary
- DAW / MIDI / audio-native workflow
- low setup friction
- experimentation
- small / medium performance rigs
- creator learning
- rapid testing of new interaction ideas

### ELM — professional spatial production

Primary mental model:

> “I need to design and run a large, precise, spatial lighting / pixel system.”

Optimise for:

- 2D / 3D mapping
- large pixel systems
- professional content workflows
- deterministic control
- precision and repeatability
- touring / installation reliability
- commissioning
- monitoring
- performance at scale

### S-PLAY / deployment layer

Where relevant, finished experiences can move into:

- scheduled playback
- unattended operation
- triggered automation
- permanent installations

---

## 2. The relationship

Do not turn ELM into “large EMU.”

Do not turn EMU into “small ELM.”

Instead:

**Creator frontier — EMU**
- discover creative problems
- test interaction ideas
- work closely with musicians / performers
- tolerate controlled experimentation

**Production frontier — ELM**
- validate professional value
- harden mature creative primitives
- expose deterministic controls
- scale to professional environments

**Deployment frontier — S-PLAY / hardware ecosystem**
- automate
- install
- operate reliably in the field

---

## 3. Feature graduation

A creative idea can take several paths.

### Stage 0 — Observation
A repeated problem appears in creator sessions, support, community or sales.

### Stage 1 — Problem validation
Confirm:
- who has the problem
- how often
- current workaround
- why current workflow is insufficient

### Stage 2 — EMU experiment
Test the smallest useful version.

### Stage 3 — Creator validation
Use it in real songs, rehearsals, videos or live performance.

### Stage 4 — EMU productisation
If value repeats, make the workflow stable and measurable.

### Stage 5 — Professional suitability review
Ask:
- does this solve an ELM user problem?
- can it be deterministic?
- can it scale?
- can it be automated / recalled?
- does it fit professional mental models?

### Stage 6 — ELM implementation
Only then consider production-grade exposure in ELM.

Possible outcomes:
1. stays EMU-only
2. becomes a shared underlying primitive with different UX
3. is rebuilt for ELM
4. becomes a service / workflow rather than a feature
5. is rejected

---

## 4. Shared Creative Engine — long-term hypothesis

If repeated cross-product transfer becomes common, ENTTEC could evaluate a shared internal creative layer.

Possible shared primitives:

- shader / generative effects
- audio analysis
- beat / section analysis
- timing primitives
- colour / transition systems
- visual grammar
- artist-defined style systems
- AI-assisted intent translation

The UX should remain product-specific.

### EMU exposes the primitive through:
- songs
- sessions
- creators
- MIDI / DAW
- simple rigs
- expressive language

### ELM exposes it through:
- spatial maps
- layers
- networked output
- professional control
- large-scale repeatability

Rule:

> **Share primitives only when it makes both products better. Do not generalise architecture for its own sake.**

---

## 5. Why this matters strategically

EMU may be smaller in system scale, but it can have disproportionate strategic value if it becomes the place where ENTTEC learns what creators want next.

ELM then benefits from creative ideas that have already been tested in human workflows rather than invented only from engineering possibility.

The portfolio story becomes:

> **EMU is where new visual language is born.  
> ELM is where selected ideas grow up.**

## 02 — 产品组合战略：EMU 负责发现，ELM 负责放大

### 战略命题

**EMU 发现新的创作语言；ELM 把经过验证的创作语言扩展成专业级生产能力。**

## 1. 保持两个产品的差异

### EMU — creator-facing experimentation

核心用户心智：

> “我是音乐人 / DJ / performance creator，我希望光成为音乐表达的一部分。”

优先优化：

- 表达速度
- music-first vocabulary
- DAW / MIDI / audio-native workflow
- 低 setup friction
- 实验性
- 小中型表演 rig
- creator learning
- 快速测试新的交互方式

### ELM — professional spatial production

核心用户心智：

> “我要设计并运行一个大型、精准、空间化的灯光 / 像素系统。”

优先优化：

- 2D / 3D mapping
- 大规模 pixel system
- 专业内容 workflow
- deterministic control

- commissioning

在合适的场景下，完成的体验可以进一步进入：

- scheduled playback
- 无人值守运行

- permanent installation

## 2. 两个产品的关系

不要把 ELM 做成“大号 EMU”。

也不要把 EMU 做成“小号 ELM”。

更合理的是：

**Creator frontier — EMU**
- 发现新的创作者问题
- 测试新的交互方式
- 和音乐人 / performance creator 紧密合作
- 容忍受控的实验

**Production frontier — ELM**
- 验证专业用户价值
- 把成熟 creative primitive 做成稳定能力
- 提供 deterministic control
- 扩展到专业级场景

**Deployment frontier — S-PLAY / hardware ecosystem**
- 自动化
- 安装
- 在真实环境里长期可靠运行

---

## 3. Feature graduation

一个 creative idea 可以走不同路径。

### Stage 0 — Observation
在 creator session、support、community 或 sales 中反复出现某个问题。

### Stage 1 — Problem validation
确认：
- 谁有这个问题
- 多频繁
- 当前 workaround
- 为什么现有 workflow 不够

### Stage 2 — EMU experiment
测试最小可用版本。

### Stage 3 — Creator validation
放到真实歌曲、排练、视频或现场表演里验证。

### Stage 4 — EMU productisation
如果价值能够重复出现，再把 workflow 做稳定、可测量。

### Stage 5 — Professional suitability review
继续问：
- 这个问题 ELM 用户也有吗？
- 能否 deterministic？
- 能否 scale？
- 能否 automation / recall？
- 是否符合 professional mental model？

### Stage 6 — ELM implementation
只有通过这些条件后，才考虑进入 ELM 的 production-grade implementation。

可能结果：

1. 只留在 EMU
2. 底层能力共享，但 UX 不同
3. 在 ELM 中重新实现
4. 变成 service / workflow，而不是 feature
5. 直接放弃

---

## 4. Shared Creative Engine — 长期假设

如果未来跨产品 feature transfer 越来越常见，ENTTEC 可以评估是否值得建立共享 creative layer。

可能共享的 primitive：

- shader / generative effects
- audio analysis
- beat / section analysis
- timing primitives
- colour / transition systems
- visual grammar
- artist-defined style systems
- AI-assisted intent translation

但 UX 应该继续按产品分开。

### EMU 的呈现方式
- song
- session
- creator
- MIDI / DAW
- simple rig
- expressive language

### ELM 的呈现方式
- spatial map
- layer
- networked output
- professional control
- large-scale repeatability

原则：

> **只有当共享底层能力真的让两个产品都变得更好时才共享，而不是为了架构统一本身。**

---

## 5. 为什么这个战略有意义

EMU 的系统规模可能更小，但如果它成为 ENTTEC 理解“创作者下一步想做什么”的入口，它的战略价值可以远大于产品规模本身。

这样 ELM 获得的不是单纯由工程可能性驱动的创意，而是已经在真实人类 workflow 里被测试过的能力。

最终 portfolio story 可以变成：

> **EMU 是新视觉语言出生的地方。  
> ELM 是其中成熟想法长大的地方。**
