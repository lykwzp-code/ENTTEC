# 05 — AI as a Creative Translator

## Product question

Can AI help a creator translate artistic intent into an editable lighting starting point **without taking authorship away from the creator**?

This is an optional product direction to test only after the underlying creator problem is validated.

---

## 1. What not to build

Avoid:

> sad song = blue lights

Avoid one-click “perfect show generation.”

Avoid an AI system that pretends there is one correct visual meaning for a song.

---

## 2. Better model

The creator remains the authority.

AI helps translate:

**artist intent  
→ musical structure / semantics  
→ perceptual / dramatic language  
→ visual grammar  
→ editable EMU / ELM controls**

Example:

Artist:

> “The final chorus should feel much wider than the first, but not more aggressive.”

System might help identify:

- relevant song sections
- spatial expansion
- intensity range
- movement logic
- transition pace
- sync / drift / restraint
- alternative visual strategies

The artist can reject, edit, combine or lock suggestions.

---

## 3. Potential layers

### Layer 1 — Creative intent
Input:
- natural language
- references
- “do / don’t” constraints
- narrative / mood description

### Layer 2 — Musical understanding
Possible signals:
- sections
- tempo
- beat
- stems / musical roles
- energy changes
- vocal entry
- harmonic / textural changes

### Layer 3 — Dramatic language
Concepts such as:
- intimate / expansive
- restrained / explosive
- still / fluid
- sparse / saturated
- near / distant
- stable / drifting

### Layer 4 — Relationship model
- sync
- delay
- counterpoint
- drift
- stochastic variation
- selective silence
- section-aware variation

### Layer 5 — Visual grammar
- intensity
- colour
- space
- movement
- density
- transition
- effect parameters

### Layer 6 — Execution
- EMU suggestions / project structures
- ELM primitives where appropriate
- editable control output

---

## 4. MVP sequence

Do not jump to full automation.

### MVP A — Intent-to-brief
AI converts creator language into a structured visual brief.

Measure:
- does creator / lighting-operator alignment improve?

### MVP B — Section-aware variation
Detect repeated song sections and suggest controlled variations.

Measure:
- less repetitive programming?
- more expressive result?

### MVP C — Relationship presets
Test concepts such as:
- synchronized
- restrained
- drifting
- counterpoint
- generative

Measure:
- can non-lighting creators understand them?

### MVP D — Artist-defined visual grammar
Allow a creator to develop a reusable vocabulary across songs.

Measure:
- reuse
- consistency
- reduced programming time

---

## 5. Artist Lab as research input

Artist Lab can create a valuable qualitative corpus:

**creator language  
→ visual decision  
→ EMU / ELM parameters  
→ creator evaluation**

Examples:

- “make the space feel emptier”
- “don’t let the bass look aggressive”
- “the second chorus should feel wider, not brighter”

Any reuse for model development would require appropriate consent, rights and data governance.

---

## 6. Guardrails

- artist can override everything
- suggestions remain editable
- uncertainty is visible where useful
- manual authoring remains first-class
- accepted output can be recalled deterministically
- system respects fixture / project constraints
- AI does not silently rewrite project logic

North-star:

> **AI assists expression; it does not automate taste.**
