# 05 — EMU Artist Lab & Community Co-Creation

## Mission

**Build tools with creators, not merely for creators.**

Artist Lab is the deeper stage that follows successful creator-market validation.

A collaboration should create three outputs:

1. a real artistic result
2. a product learning
3. authentic content

---

## 1. Design partner first, endorsement second

Do not ask only:

> “What feature do you want?”

Ask:

- What should the audience feel here?
- What visual behaviour would ruin the song?
- Where should light deliberately not follow the beat?
- Should the second chorus feel different from the first?
- What part of the song carries the emotional weight?
- If you avoid lighting terminology, how would you describe what you want?

The product research team translates those answers into testable product problems.

---

## 2. Music-to-Light Visual Grammar

Artist Lab should study a more fundamental question:

> **How does a musician decompose their own music, what role does each element play, and how should that role — if at all — become visible?**

This is different from technical stem separation.

Do not begin with:

> “Here are drums, bass, vocals and synths. What colour should each one be?”

Begin with:

> “When you hear your own song, what are the elements you actually care about, and what is each one doing to the listener?”

Research model:

**musical element  
→ artist-defined role  
→ artistic intent  
→ desired visual relationship  
→ visual primitive  
→ EMU implementation  
→ artist evaluation**

The same bass line may represent:

- pressure
- movement
- sensuality
- background stability
- something that should remain visually quiet

No universal mapping should be assumed.

---

## 3. Suggested workshop flow

### Step 1 — Artist-led song decomposition
Use one real song.

Ask the artist to mark:
- sections
- important entrances / exits
- repeated sections that should feel different
- elements they personally consider important

### Step 2 — Define artistic roles
For each important element:
- What is it doing emotionally?
- Is it foreground or background?
- Is it weight, tension, motion, intimacy, release, emptiness or something else?
- Should the audience consciously notice it?

### Step 3 — Define visual relationships
Ask:
- direct sync?
- delay?
- drift?
- counterpoint?
- spatial influence rather than brightness?
- visual silence?
- transition-only behaviour?

### Step 4 — Translate into visual primitives
Possible dimensions:
- intensity
- colour
- spatial width
- focus
- movement
- density
- transition
- foreground / background
- repetition / variation
- stillness

### Step 5 — Build and compare
Where useful, create alternatives.

Ask:
- Which version actually feels like the song?
- Which is technically impressive but artistically wrong?
- What is missing from EMU?
- What would make this easier next time?

### Step 6 — Capture the grammar
Record:
- musical element
- artistic role
- desired visual behaviour
- implementation
- limitation / workaround
- artist evaluation

---

## 4. Pilot structure

Suggested:
- 3–6 months
- emerging / mid-scale artists
- dancers / choreographers where relevant
- occasional larger guest

High-profile artists should amplify the program, not be required for it to work.

---

## 5. Recurring host / Artist-in-Residence

A recurring creator can become:

- host
- learner
- educator
- community bridge

The audience can watch the person grow from:

> “I am not a lighting designer.”

to:

> “I can help another creator build a visual performance.”

A sensible partnership path:
- 3–6 month pilot
- 12-month agreement
- longer extension only after fit is proven

---

## 6. Episode structure

1. **Intent** — artist explains the work
2. **Translation** — build visual language
3. **Build** — make the best current EMU version
4. **Friction** — show limitations and failed ideas
5. **Final work** — real audiovisual performance
6. **Product learning** — record problem, evidence and next action

---

## 7. Return episode

A limitation can become a long-term story.

Example:

- Episode 4: artist asks for something EMU cannot express
- Episode 10: another creator tests a prototype
- Episode 15: capability reaches beta
- Episode 18: original artist returns with a new song

Possible title:

> **We finally built what they asked for.**

This makes product development visible and human.

---

## 8. Artist Intent Card

Record:

- Artist / creator
- Song / project
- Desired audience feeling
- Key musical / dramatic moments
- Musical elements and roles
- Visual grammar
- Current EMU method
- Friction
- Missing capability
- Workaround
- Evidence from other creators
- Status: exploring / prototype / not planned / released

Important:

> **Backlog is not a roadmap promise.**

---

## 9. Community as discovery

### YouTube
Full creative process.

### TikTok / Reels / Shorts
Strongest finished performance.

### Comments
Treat comments as hypotheses, not roadmap votes.

If someone asks:

> “Can EMU understand lyrics?”

ask what the underlying need is:
- semantics?
- narrative?
- section awareness?
- something else?

---

## 10. The loop

**creator intent  
→ real workflow  
→ visible friction  
→ product hypothesis  
→ experiment  
→ creator validation  
→ product change  
→ new content  
→ new creators**

Content, research, product and community reinforce each other.

# 中文版

## 05 — EMU Artist Lab 与社区共创

### Mission

**和创作者一起做工具，而不是只为创作者做工具。**

Artist Lab 是 creator-market validation 成立以后更深入的一层。

每次合作同时产生：

1. 真正作品
2. 产品学习
3. 真实内容

---

## 1. Design partner first, endorsement second

不要只问：

> “你想要什么功能？”

应该问：

- 这一段希望观众感受到什么？
- 什么视觉会毁掉这首歌？
- 哪些地方灯光反而不应该跟 beat？
- 第二次副歌为什么应该和第一次不同？
- 哪一段真正承载情绪？
- 不用灯光术语，你会怎样描述想要的效果？

产品研究团队把这些回答转化成可验证的产品问题。

---

## 2. Music-to-Light Visual Grammar

Artist Lab 应该研究一个更基础的问题：

> **音乐人自己到底怎样拆解自己的音乐？每一个元素在表达上承担什么作用？这些作用又应该怎样——或者是否应该——被视觉化？**

这和技术 stem separation 不一样。

不要一开始就说：

> “这里是 drums、bass、vocals、synths，每一个应该是什么颜色？”

而应该问：

> “你自己听这首歌时真正注意哪些元素？每个元素到底在对听众做什么？”

研究模型：

**musical element  
→ artist-defined role  
→ artistic intent  
→ desired visual relationship  
→ visual primitive  
→ EMU implementation  
→ artist evaluation**

同一个 bass 可能代表：

- 压迫
- 运动
- 身体感
- 背景稳定
- 或者虽然重要，但视觉上应该保持安静

不能预设 universal mapping。

---

## 3. Workshop 流程

### Step 1 — 音乐人自己拆歌
使用真实作品。

标记：
- section
- 重要进入 / 退出
- 哪些重复段落应该视觉不同
- ta 自己真正重视的元素

### Step 2 — 定义表达作用
继续问：
- 情绪上在做什么？
- foreground 还是 background？
- 是重量、tension、movement、intimacy、release、emptiness 还是别的？
- 观众是否应该明显注意？

### Step 3 — 定义视觉关系
- direct sync？
- delay？
- drift？
- counterpoint？
- 影响空间而不是 brightness？
- visual silence？
- 只在 transition 出现？

### Step 4 — 翻译成 visual primitive
- intensity
- colour
- spatial width
- focus
- movement
- density
- transition
- foreground / background
- repetition / variation
- stillness

### Step 5 — 做出来比较
问：
- 哪个最像这首歌？
- 哪个技术很炫但艺术上错了？
- EMU 缺什么？
- 下次怎么更快？

### Step 6 — 记录 grammar
记录：
- musical element
- artistic role
- desired visual behaviour
- implementation
- limitation / workaround
- artist evaluation
