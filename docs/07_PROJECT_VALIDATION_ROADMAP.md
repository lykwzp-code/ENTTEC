# 07 — Project Validation Roadmap (Proposed)

This is an **independent product research proposal**. It is not an ENTTEC-approved launch plan or a committed implementation schedule.

## Goal

Test three connected hypotheses without prematurely committing to a full platform redesign:

1. A beginner creator can achieve a meaningful light-and-music result with less technical friction.
2. Dance, performance, studio and livestream creators may represent incremental demand for EMU.
3. Artist-led Music-to-Light Visual Grammar research may yield reusable, editable creative controls.

Progress only when the preceding evidence is sufficient.

---

## Phase 1 — Baseline and feasibility (suggested first 30 days)

Research existing EMU and ELM workflows, licensing tiers, DMX setup and compatible hardware.

Compare:
- first-run experience for novices versus experienced users
- where fixture/patching requirements interrupt first success
- current template/effect customization possibilities
- audio-reactive controls versus artist-directed expression
- the practical constraints of a small physical starter rig
- ELM handoff/use cases (without assuming an automatic upgrade path)

**Outputs:** workflow map, feasibility notes, preliminary activation baseline, candidate experiments.

**Decision gate:** can we build a meaningful beginner pilot without changing the entire core engine?

---

## Phase 2 — Local discovery in Guangzhou (suggested days 31–60)

A small, convenience-sampled design-partner cohort could include:
- one dance studio
- one dance crew or choreographer
- one livestream / MCN team
- one independent musician / producer
- one small content-production team

Also interview experienced EMU users and a small sample of ELM professionals to protect advanced workflows.

Separate research questions:

**Creator/Dance**
- Is lighting central enough to the creator's outcome?
- Can they set up and change a look without a technician?
- Would they reuse the setup on another song or shoot?

**Livestream/MCN**
- How often do they change themes?
- Is manual switching a cost or reliability problem?
- What must work consistently over long sessions?

**Music-to-Light**
- How does the artist decompose a song?
- What is each musical element expressing?
- Which visual relationships should be synchronized, delayed, restrained or intentionally absent?

**Outputs:** problem taxonomy, job-to-be-done maps, candidate visual grammar, segment-specific go/no-go criteria.

**Decision gate:** is there repeated friction and credible willingness to adopt, not merely enthusiasm for a demo?

---

## Phase 3 — Small, bounded experiments (suggested days 61–90)

### Experiment A: Quick → Creator → Advanced workflow
A prototype or controlled workaround may test:
1. choose music and starter hardware layout
2. select a template
3. produce first useful result
4. customize a section
5. reveal advanced controls without losing work

Measure task completion, time, confusion, reusability and how much expert help was required.

### Experiment B: Reimagined in Light
Produce 2–3 rights-cleared video/performance concepts. Where practical, include:
- a dance creator
- a livestream/studio use case
- a clear path from viewing to a tutorial, template or product trial

**Avoid using copyrighted catalogue tracks without appropriate permission.**

Measure not only video views but qualified creator actions and subsequent use.

### Experiment C: Music-to-Light workshop
With a musician, build 2–3 different visual treatments for a real section of their work. Record:
- artist-defined musical roles
- intended meaning
- visual choices
- technical constraints
- creator's evaluation and changes

Measure whether a reusable creative primitive emerges.

---

## Phase 4 — Repeatability and portfolio decision (suggested months 4–6)

If early results support it:
- repeat the creator workflow test with different backgrounds
- test starter hardware/configuration packages and real support cost
- refine editable templates and learnable controls
- formalize a small Artist Lab only if the collaborations reliably yield useful insight
- assess AI only if manual intent translation is a repeated pain point
- assess ELM transfer only if professional users independently validate the use case

Possible outcomes:
- continue / scale a specific experiment
- redesign onboarding rather than build a new feature
- keep a capability EMU-only
- move a proven capability into professional suitability review
- stop a weak market or AI hypothesis

---

## Evidence dashboard

| Category | Useful signals | Misleading substitute |
| --- | --- | --- |
| Acquisition | qualified EMU trials from creator content | views alone |
| Activation | first working show, time and help required | software download alone |
| Retention | second project, repeat editing / publishing | one sponsored video |
| Creator control | first meaningful customization | selecting a preset once |
| Hardware | setup success, support burden, repeat purchases | hardware interest alone |
| Product discovery | repeated user pain and validated experiments | feature wishlists |
| Portfolio | professional use cases confirmed by ELM users | assuming every EMU feature graduates |

Record baseline and sample size for each experiment; do not invent percentage targets before access to data.

# 中文版

## 07 — 项目验证路线图（设想）

这是**产品项目本身**的研究与试验计划，不是候选人入职安排，也不是 ENTTEC 已批准的项目。

### 目标

以小规模实验验证三条相互关联的假设：

1. 新手能否在较低技术门槛下快速做出真正有用的音乐灯光作品？
2. 舞团、练舞房、小型内容团队与团播/MCN 是否构成 EMU 的增量市场？
3. 和音乐人一起研究 Music-to-Light Visual Grammar，能否发现可复用、可编辑的表达原语？

没有足够证据时，不应直接扩大投入。

### Phase 1 — 现状与可行性（建议前 30 天）

了解 EMU / ELM 当前能力、授权、DMX 与实际硬件接入。对比新手和熟手完成第一支作品的路径，找出 template、灯具配置、audio-reactive、深入自定义的摩擦。

**产出：** 用户流程图、技术/物理门槛记录、第一版实验计划。

**决策门槛：** 不大规模改核心引擎，是否也能测试新手体验？

### Phase 2 — 广州本地发现（建议第 31–60 天）

先联系少量合作对象：舞蹈室、舞团/编舞、团播/MCN、独立音乐人、视频制作团队各一类。同期了解现有 EMU 用户与少量 ELM 专业用户。

分开研究：
- **舞蹈创作者：** 能否自己布置、使用、修改，下一次还愿不愿意用？
- **团播/MCN：** 高频换主题、长期稳定、操作员学习成本是不是痛点？
- **音乐人：** 音乐元素承担什么表达角色；哪些应该与光同步、延迟、克制或保持静止？

**产出：** 问题分类、用户任务图、初步 visual grammar、各细分市场验证标准。

**决策门槛：** 是否真的存在重复问题、现实采用意愿？

### Phase 3 — 小规模实验（建议第 61–90 天）

**A. 新手到专业的渐进体验：** 选歌 → 选 setup → 用模板 → 修改一个段落 → 展开高级控制。记录成功时间、完成率、理解难点、专家协助量。

**B. Reimagined in Light：** 用已授权音乐做 2–3 个光影内容试验，尽可能加入舞团和工作室/直播场景。测视频观看后的真实产品行为，不能只看播放量。

**C. Music-to-Light Workshop：** 和音乐人针对真实歌曲建立 2–3 种视觉演绎版本，记录元素的艺术角色、希望的关系、控制参数、限制和真实评价。

### Phase 4 — 验证可重复性（建议第 4–6 个月）

如果前面有证据支持，再扩大：
- 新手体验测试
- starter hardware 套餐与支持成本测试
- 可编辑 template
- Artist Lab 合作
- 经过用户证明值得做的 AI 辅助
- 经过专业用户验证的 EMU → ELM 能力迁移

允许选择不做某些 feature，甚至终止不成立的市场假设。

### 测量原则

| 类别 | 应测什么 | 不能用什么代替 |
| --- | --- | --- |
| 获客 | 从内容进入的有效 EMU 试用 | 播放量 |
| 激活 | 第一个真实灯光秀、完成时间、所需帮助 | 下载量 |
| 留存 | 第二次创作与重复编辑/发布 | 一次品牌合作 |
| 自定义 | 首次有意义的修改 | 只套用一次模板 |
| 硬件 | 接入成功率、支持成本、后续升级 | 口头感兴趣 |
| 产品发现 | 可重复的问题与验证实验 | 功能愿望清单 |
| 产品组合 | ELM 专业用户也认可的需求 | 认为所有 EMU 功能都应迁移 |

每轮记录样本量与基线，拿不到数据时不要提前发明达标数字。
