# 07 — 180-Day Execution Plan

## Goal

In six months, prove or disprove the core strategy with evidence.

Do not join and immediately build the full vision.

Use:

**Learn → Discover → Experiment → Prove**

---

## Days 0–30 — Learn

### Product
- use EMU end-to-end as a creator
- use ELM enough to understand professional workflow and product boundaries
- understand S-PLAY / deployment use cases
- map the relevant hardware ecosystem

### Organisation
- shadow Product, Engineering, Support, Sales and Marketing
- understand roadmap / resource decisions
- clarify Product Specialist ownership and escalation paths

### Evidence
- review support themes
- review existing customer / artist cases
- identify recurring user friction

### Deliverables
- ecosystem map
- role / decision-rights map
- top workflow-friction list
- first research plan

---

## Days 31–60 — Discover

### Creator side
- 10–15 musician / producer / performance-creator interviews
- observe real workflows where possible
- include dance / K-pop creators if market evidence supports it

### Professional side
- 5–10 ELM designer / integrator / professional-user interviews

### Outputs
- creator journey
- professional journey
- recurring problem taxonomy
- top 3 hypotheses
- first content-market test design

### Gate
Do not build a large AI feature or a large Artist Lab program yet.

---

## Days 61–90 — Experiment

### Content-led market test
Launch a small **Reimagined in Light** pilot using rights-cleared music.

Possible pilot:
- 2–3 episodes
- at least one dance / performance collaboration
- clear call-to-action into EMU learning or trial

### Product test
Choose one repeated workflow problem.

Test:
- prototype
- workflow mock
- manual-assisted process
- template
- small beta

Define success and kill criteria before testing.

### Community
Start comments-to-hypotheses process.

---

## Months 4–6 — Prove

If early evidence is strong:

### Market
- repeat the content format
- test studio / dance-creator demand
- measure qualified EMU trial / adoption

### Co-creation
- launch a small Artist Lab pilot
- recruit 3–5 design partners
- create Artist Intent Cards
- test at least one repeated product problem

### Product
Decide:
- ship
- iterate
- kill
- keep as workflow / service

### Portfolio
Only after creator value is proven:
- evaluate whether any mature primitive has ELM relevance

---

## KPI hierarchy

Do not optimise only for views.

### Product discovery
- validated problems
- time from insight to test
- percentage of weak hypotheses killed early
- experiments tested with multiple creators

### Creator activation
- time to first expressive show
- first-project completion
- repeat creation
- creator independence from expert support

### Market
- qualified EMU downloads
- creator / studio inbound interest
- template / tutorial usage
- repeat use after collaboration

### Content
- completion rate
- return viewers
- high-intent comments
- creator applications

### Portfolio
- reusable creative primitives
- professional validation
- successful EMU → ELM graduation where justified

---

## Six-month decision

At the end of the period, answer:

1. Does creator-intent translation solve a repeated problem?
2. Is content an effective acquisition + research channel?
3. Is dance / performance creation a real adjacent market?
4. Does Artist Lab produce better product evidence than conventional feedback alone?
5. Is there a validated AI opportunity, or is simpler workflow design sufficient?
6. Are any creative primitives genuinely relevant to ELM?
7. Does the Product Specialist role have enough ownership and resources to continue the loop?

A good six-month outcome can include killing weak ideas. Learning is the objective, not defending the original concept.
